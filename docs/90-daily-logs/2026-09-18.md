## 00:27 · dev-implement (PLAN-0001, bug fix) — orchestrator (inline)
- User hit a runtime error running the real app: `Error invoking remote method
  'dataLocation:createInFolder': Error: Could not dynamically require
  ".../build/better_sqlite3.node"` after choosing a folder in Onboarding.
- Root cause: `vite.config.ts`'s electron main/preload rollup build had no `external` list, so
  rollup bundled `better-sqlite3` (a native addon) into `dist-electron/main.js` once AT-1.6
  wired `electron/main.ts` → `src/main/dataLocation.ts` → `better-sqlite3`. Rollup can't
  statically resolve the addon's dynamic `.node` require — fails at runtime only, not at
  build/typecheck/lint, which is why it wasn't caught until real use.
- Fix: externalize every `package.json` `dependencies` entry for the main/preload builds
  (standard vite-plugin-electron pattern). Verified by building and grepping
  `dist-electron/main.js`: 0 occurrences of the inlined `.node` path, a plain
  `require("better-sqlite3")` instead; bundle size dropped ~200KB → 170KB; Electron window
  launches without error. 110/110 tests, lint, tsc still clean (unaffected — this bug only
  showed up in the actual bundled+run output).
- commit `97aa735` (code), correction note appended to `AT-1.1.md` (the scaffold task that
  wrote `vite.config.ts`). Fast-forwarded + pushed `main`.
